# W4.11 Independent Adversarial Review

Date: 2026-08-29

## Scope

The review challenged the W4.11 identity/session management API, exact permission manifest,
actor-aware audit attribution, opaque session references, recovery status, repository pagination,
and secret-minimizing response contracts. It was performed from fresh context after the initial
implementation and before the slice checkpoint.

## Reconciled findings

### Recovery ingress status followed configuration incorrectly

The recovery status endpoint always reported `direct_loopback_only`, even when
`LOCAL_RECOVERY_ONLY` disabled that enforcement. This could mislead an operator about the real
exposure boundary.

Resolution: one `recovery_local_only_enabled()` policy helper now drives both request enforcement
and the management status response. The response reports exactly `direct_loopback_only` or
`network_reachable`, and route tests cover both configurations.

### SQLite pagination order lacked a matching index

Identity pages use stable `(created_at, identity_id)` ordering, but SQLite had no matching index.
The result was correct but could degrade as an enterprise identity inventory grows.

Resolution: SQLite initialization now creates `idx_management_identity_order` over the stable
pagination tuple, with a schema test preventing regression. PostgreSQL and MongoDB retain the same
logical cursor contract.

## Confirmed boundaries

- No concrete authorization bypass, owner-role escalation, or bearer/session-secret disclosure was
  found.
- Owner transitions require the dedicated `owners.manage` permission and still pass repository
  invariants and optimistic revision checks.
- Identity and OIDC-policy mutations invalidate authorization epochs durably; eager process-local
  session cleanup is best effort and is reported without weakening the durable invalidation.
- Session inventory exposes domain-separated HMAC references, never bearer tokens or internal token
  digests. Identity responses omit provider tokens, profile claims, groups, and configured secrets.
- Audit actor identifiers are typed and HMAC-redacted before persistence; verified authorization
  denials retain the authenticated principal instead of collapsing to an anonymous actor.

## Closure evidence

- 946 backend tests pass; 14 opt-in live-backend tests are skipped because no live test URI is
  configured.
- Repository Ruff lint/format, compileall, dependency consistency, frontend JavaScript syntax, diff
  whitespace, and dependency vulnerability checks pass.
- W4.12 remains responsible for the localized browser console and its responsive, accessibility,
  locale, permission, DOM-secret, console, and network matrices.
