### P2: pagination re-entrancy

Rapid repeated Next/Previous activation could reuse the previous `next_cursor`, append duplicate
backstack entries, and advance the displayed page more than once before the first request returned.

Reconciliation:

- Added independent identity-page and session-page single-flight state.
- Both cursor transitions clear the consumed next cursor immediately.
- Previous and Next controls remain disabled for the complete request lifetime.
- Executable client tests issue simultaneous duplicate triggers and prove one request, one page
  transition, and one backstack entry for both resources.

### P2: create-conflict semantics

`POST /api/identity/identities` uses HTTP 409 for an existing exact `(issuer, subject)` pair, not a
CAS revision conflict. The console incorrectly rendered the stale-revision message.

Reconciliation:

- Creation conflicts now render a dedicated `identity.already_exists` message.
- The message has curated copy for all 15 supported locales.
- An executable client test proves that HTTP 409 on create selects the collision message rather
  than the CAS message.
