# W4.17 Routing, Governance, and Cache Coordination Implementation Plan

## Goal

Complete the routing/governance/cache portion of the accepted HA state boundary while preserving
standalone behavior and keeping coordinated activation closed.

## Internal slices

1. **Inventory and contract** — commit this specification, exact ownership table, bounds, failure
   posture, and resumable task state.
2. **Readable fenced records** — RED/GREEN a closed-schema `CasSnapshot`/`read_cas` primitive in the
   domain, in-memory reference, Redis script/decoder, service metrics, shared contract, and live
   harness.
3. **Semantic coordination adapter** — RED/GREEN HMAC identifiers, bounded credential lease and
   route-outcome records, exact/semantic cache metadata, monotonic invalidation, fixed retries, and
   corrupt-payload failure.
4. **Router migration** — inject the adapter and epoch into `SmartCredentialRouter` and
   `CredentialManager`; use shared snapshots/CAS leases/cooldowns without fallback, preserving
   ranking and response contracts.
5. **Quota migration** — remove truthiness fallback and hard-coded epoch assumptions from
   `VirtualKeyManager`; prove shared-manager concurrency and lifecycle behavior.
6. **Cache migration** — put exact-cache admission behind the adapter, keep bytes local, validate
   digest/generation on every hit, and add cross-replica invalidation tests. Keep semantic runtime
   inactive.
7. **Governance invalidation** — add an injected generation observer/publisher for mutable config,
   credential state, virtual-key metadata, model blacklist, and model catalog caches. Cross-replica
   misses reload durable authority and failures close unsafe admission.
8. **Operability and live parity** — fixed-cardinality metrics, opt-in Redis live tests, restart and
   failure/cancellation cases, bounded cleanup/capacity evidence, and measured adapter microbenchmarks.
9. **Adversarial review and closure** — independently re-read the diff against ADR-006/008, resolve
   findings through RED/GREEN tests, run affected and full repository gates, update operator,
   architecture, changelog, and task records, commit, restart committed code, and prove one healthy
   listener.

## Verification cadence

- Each behavior slice: failing test, minimal implementation, focused regression, Ruff/format,
  diff review, atomic commit.
- After slices 3, 6, and 8: full coordination/routing/quota/cache affected matrix.
- Closure: full backend suite; frontend syntax and route contracts; dependency, YAML, shell,
  compile, whitespace, tracked-secret, and available secret-scan gates; opt-in skips explicitly
  counted; committed runtime health/readiness and clean worktree.

## Non-goals

- No Redis/runtime mode selection, multi-replica deployment, or readiness claim (W4.18).
- No production migration, scale-out activation, or external source transfer.
- No prompt, embedding, response body, raw credential name, model name, or virtual-key identifier
  in Redis or metric labels.
- No semantic-cache activation or authenticated distributed content store.
