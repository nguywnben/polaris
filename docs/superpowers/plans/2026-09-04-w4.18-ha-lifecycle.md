# W4.18 HA lifecycle implementation plan

## Goal

Implement a single fail-closed runtime owner and safe operator/deployment surface while preserving
standalone compatibility and withholding HA activation until W4.19.

## Internal slices

1. Specify the closed environment policy, persistent binding, state machine, command semantics,
   readiness projection, deployment ceiling, and retained activation gate.
2. RED/GREEN a pure policy parser with a complete standalone/coordinated contradiction matrix and
   secret-free representation.
3. RED/GREEN versioned durable/Redis binding validation, namespace-loss detection, bootstrap
   preflight, and exact fencing-epoch lifecycle transitions.
4. Build one lifecycle owner and inject its shared service into security, routing, quota,
   governance, and exact-cache consumers before they initialize.
5. Make readiness lifecycle/dependency aware while keeping liveness independent; add bounded
   content-free metrics and failure recovery tests.
6. Add dry-run-first drain, advance, reconcile, mark-ready, status, and rollback-plan commands with
   stable operation IDs and no automatic deletion or durable authority switch.
7. Update Compose, Helm, container, examples, alerts, and runbooks with standalone defaults,
   secret references, termination behavior, and the W4.18 one-replica ceiling.
8. Verify policy/render matrices, lifecycle and command smoke, namespace protection, standalone
   startup, affected/full gates, then reconcile adversarial review and close the checkpoint.

## Activation rule

The implementation may prove coordinated behavior with deterministic test stores, but runtime
bootstrap and a multi-replica claim remain unreachable without the canonical migration readiness
and W4.19 activation record. Skipped live infrastructure is recorded as unavailable evidence.
