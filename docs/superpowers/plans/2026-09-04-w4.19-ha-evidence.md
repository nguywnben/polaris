# W4.19 HA evidence and activation-disposition plan

## Goal

Produce reproducible failure/load evidence, resolve or retain every activation blocker explicitly,
and close Wave 4 without claiming coordinated availability when external topology evidence is
missing.

## Internal slices

1. Add a non-secret in-process evidence harness for one logical client versus two logical clients,
   atomic shared state, dependency interruption, stale fencing, recovery, and namespace loss.
2. Run the accepted coordination/security/routing/cache/quota failure suites and opt-in live suites.
3. Measure bounded synthetic latency/throughput and inventory algorithms whose production cost was
   not measured on Redis.
4. Inventory remaining process-local correctness state and distinguish activation blockers from
   disposable caches.
5. Run every available repository, dependency, manifest, browser, accessibility, i18n, telemetry,
   security, diff, and secret gate; label missing infrastructure unavailable.
6. Record the activation disposition. Populate no allowlist entry unless the exact external
   topology passes every ADR-008 target.
7. Reconcile final review, documentation, task state, committed restart, and clean-tree evidence.

## Safety rule

Synthetic or fake-driver results prove deterministic semantics only. They can never satisfy the
live Redis/durable-database/container/two-replica activation requirement.
