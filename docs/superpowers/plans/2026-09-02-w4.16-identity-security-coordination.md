# W4.16 Identity and Security State Coordination Implementation Plan

**Goal:** Coordinate management sessions, authentication throttles, OIDC one-time state, and
security invalidation through the W4.15 fenced boundary without activating Redis or scale-out.

**Architecture:** `core/security_coordination.py` defines opaque, typed security-state operations.
`InMemoryStateStore` is the executable reference and standalone default; `RedisStateStore` uses
fixed bounded Lua scripts behind the same protocol. Identity adapters own HMAC/encryption codecs,
and callers never see Redis commands.

**Spec:** `docs/specs/identity-security-coordination.md`

## Global constraints

- Keep `WORKERS=1`, one replica, source authority, existing `/ready`, and every HA activation gate.
- Do not add a Redis selection switch or migrate routing/quota/cache callers in W4.16.
- Follow RED -> GREEN -> REFACTOR for every behavior change and commit each approved task.
- Every security allow/admission decision requires the exact ready fencing epoch and fails closed
  for unavailable, corrupt, partial, stale, reconciling, capacity, or cleanup-backlog state.
- Redis keys, telemetry, logs, errors, and representations contain no bearer, OIDC proof, raw client
  address, raw identity, or secret.
- Live Redis is opt-in; an absent URI is an explicit skip, not evidence.
- Do not push or send source externally without an explicit human request for that action/artifact.
