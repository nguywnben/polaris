# Polaris identifier contract

Polaris uses one canonical identity throughout the complete product surface. This pre-release
cutover intentionally does not provide compatibility aliases because no public installation or
client depends on an earlier build.

## Distribution

- Repository: `https://github.com/nguywnben/polaris`
- Docker Hub: `nguywnben/polaris`
- GitHub Container Registry: `ghcr.io/nguywnben/polaris`
- Compose project: `polaris`
- Compose data volume: `polaris-data`

## Client and runtime contracts

- Generated API key prefix: `sk-polaris-`
- Default virtual model and route alias: `polaris`
- Product-owned environment prefix: `POLARIS_`
- Product-owned HTTP header prefix: `X-Polaris-`
- Prometheus metric prefix: `polaris_`
- OpenTelemetry namespace: `polaris.`
- Browser event namespace: `polaris:`
- Browser storage namespace: `polaris_` or `polaris.` according to the owning feature

Backup envelopes, signed cursors, encrypted payloads, session artifacts, recovery records, and
other persisted security state also use versioned Polaris domains. Artifacts generated by a
pre-release build are not accepted as Polaris artifacts. Start from a fresh `polaris-data` volume
or import provider credentials again through the supported UI.

## Release rule

New product-owned identifiers must use the Polaris namespace. Adding a compatibility alias needs
an explicit post-release migration plan, contract tests, and a documented removal policy.
