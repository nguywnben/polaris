## Contract

The change adds a dedicated enterprise `/identity` console over the existing W4.11 API only. It
must:

- show the effective current principal and exact permissions, safe OIDC readiness, recovery status,
  bounded direct identities, and bounded active sessions;
- derive every visible/enabled control from exact effective permissions while retaining the server
  as the authorization boundary;
- support direct-identity creation, enablement, role binding, session revocation, and OIDC
  authorization-epoch advancement through only the W4.11 endpoints;
- require explicit native-dialog confirmation for owner-affecting, access-removing, session, role,
  and policy-epoch mutations;
- send the correct CAS revision, refetch after HTTP 409, and preserve mutation-specific operator
  input for review against the fresh revision;
- block repeated in-flight submissions and deliberately restore focus after list replacement;
- visibly sign out the current OIDC principal after any successful self-mutation or policy-epoch
  advancement that invalidates its session, and sign out after current-session revocation;
- clear all identity data, drafts, permissions, cursors, dialogs, and tab-cache state across every
  authentication boundary;
- abort and generation-guard all asynchronous resource loads so an old principal's response cannot
  repopulate state after logout or principal change;
- independently bound and validate untrusted permissions, page collections, cursors, OIDC scopes,
  records, and safe projections before logic or DOM rendering;
- render untrusted values only through DOM text APIs and never place bearer/session tokens, token
  digests, OIDC secrets, passwords, profile claims, or groups in DOM fields, logs, `localStorage`, or
  `sessionStorage`;
- provide complete curated copy for the existing 15 locales while leaving role, principal,
  authentication, source, readiness, and ingress protocol codes exact;
- remain responsive and keyboard/focus accessible at 360, 768, 1024, and 1440 pixels under light,
  dark, and system themes;
- leave OIDC disabled by default and make no auth-flow, backend API, role-definition, dependency,
  persistence, worker, replica, or deployment-topology change.
