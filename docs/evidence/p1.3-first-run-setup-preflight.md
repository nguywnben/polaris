# P1.3 — First-run Setup and Preflight

Date: 2026-09-09
Plan: `PROD-SELFHOST-R1`

## Result

First-run setup now has one explicit state contract for `fresh`, `resumed`, `configured`, and
`invalid` installations. The status and preflight APIs report exactly one next action plus bounded,
secret-free checks for durable data writes, the effective console address, listener, transport and
cookie expectations, setup-token policy, and owner state.

Successful preflight stores only `{"version": 1, "preflight": "passed"}` so an interrupted setup
can resume without persisting a password or token. Owner creation is serialized, refuses failed
durable writes, and requires a non-common passphrase of 12–256 characters. Remote setup fails
closed unless the operator configures a sufficiently diverse `SETUP_TOKEN` of at least 24
characters. Polaris no longer generates or prints that secret. Direct loopback setup remains
token-free; a loopback origin published through Docker is accepted as local transport only while
the existing client-address policy continues to require token authentication.

The setup console presents the check results and one recovery action before enabling owner fields.
It uses semantic lists, an announced status region, bounded inputs, visible non-color status text,
body-only secret submission, and clears submitted secrets. English and Vietnamese have curated
setup copy; community locales retain their existing authentication translations and receive the
complete English preflight fallback. Operator documentation in every shipped README locale now
matches the non-logging token policy.

owner creation, and container-origin behavior. Security review traced host/proxy headers, token and
password input, checkpoint persistence, logging, URL/history use, and DOM rendering; secrets remain
in request bodies only and untrusted response values are assigned through `textContent`.
Readability and architecture review kept preflight policy in the panel boundary and reused the
canonical origin/cookie helpers without adding a dependency. Accessibility review removed opacity
from disabled explanatory content and browser checks confirmed responsive, keyboard-operable
behavior. No release-blocking correctness, security, architecture, performance, or accessibility
finding remains.
