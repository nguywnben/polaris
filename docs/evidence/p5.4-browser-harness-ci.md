# P5.4 — Browser Test Harness and CI Balance

Date: 2026-09-11  
Implementation candidate: `593eed2`  
Plan: `PROD-SELFHOST-R1`

## Outcome

P5.4 is complete. `tools/browser_smoke.py` is now an active release-gate step and a required CI job.
It launches one isolated headless Chromium instance against a fresh loopback-only Polaris
runtime with disposable SQLite state. Provider validation, discovery, route creation, and inference
responses are deterministic browser fixtures; no real provider, account, credential, or upstream
network call is used.

The browser dependency is isolated in `requirements-browser.txt` and pinned. CI caches the locked
runtime and browser requirement inputs, installs only Chromium, and runs browser smoke in parallel
with the existing container smoke after Python verification. Container publication and releases now
require both jobs. Firefox/WebKit and experimental HA matrices were deliberately not added.

## Required Journey Coverage

1. Fresh install preflight, owner setup, and healthy dashboard.
2. Ollama credential submission, deterministic validation, and model discovery.
3. `omway` route creation plus non-streaming and streaming response rendering.
4. AI Quality inspection, custom policy selection, compression disable, and live save.
5. Playground execution, route/quality metadata, and a placeholder-only client example.
6. Real virtual-key create, authenticated use, rotate, and revoke lifecycle.
7. Request-ID Activity filtering with provider, token, cost, and redaction assertions.
8. Discoverable backup/restore and update/rollback operating guidance.
9. Disabled optional OIDC with independently ready local-owner recovery.

After those journeys, the same authenticated session visits all 11 console routes at 360, 768,
1024, and 1440 px. Every active route must expose exactly one visible H1, every visible form control
must have an accessible name, and the document must not overflow horizontally.

## Production Defects Found by the Harness

- Console startup was attached only to `window.onload`, allowing an unavailable external font/style
  resource to delay setup and login. Startup now runs at `DOMContentLoaded`, including the safe case
  where the DOM is already ready when the bundle executes. A static regression contract protects it.
- Activity's request-ID `pattern` used a hyphen form rejected by Chromium's current HTML Pattern
  `v`-mode parser. The hyphen is now escaped and the shared filter submits without a console error.
