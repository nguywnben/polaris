## Production Boundary

This task evaluates the supported standalone, one-worker, one-replica self-host target. SQLite and
the local owner are Core. OIDC and PostgreSQL are optional Advanced surfaces. MongoDB remains a
Compatibility surface. SaaS multi-tenancy, HA, Kubernetes, and untrusted organization-wide
delegation are outside the release claim.

The review covered local setup/login/recovery, opaque sessions, management authorization, virtual
keys, optional OIDC, OAuth credential onboarding, CORS/proxy/cookie policies, uploads/imports,
SSRF, browser rendering, request limits, secret handling, dependency state, and the canonical
container profile.

## Negative Findings

- Local setup requires direct loopback access or a strong configured setup token; first-owner
  creation is serialized and validates durable storage before committing the owner.
- Local-owner recovery uses the local password, its own bounded rate window, optional direct
  loopback restriction, opaque session issuance, and auditable unauthenticated outcomes. It does
  not depend on OIDC availability.
- Session secrets are random opaque values; persisted coordination state uses keyed indexes and an
  authenticated encrypted payload. Idle/absolute expiry, rotation, revocation, identity epochs,
  and OIDC policy epochs fail closed in the adversarial session suite.
- The authorization manifest exactly matches every protected HTTP operation and management
  WebSocket. Unknown routes/transports fail closed, and legacy virtual-key scopes gain no identity,
  owner, recovery, or HA authority.
- OIDC discovery/token/JWKS transport allows only configured HTTPS origins, validates a single DNS
  snapshot, rejects unsafe/mixed addresses outside an explicit private-host exception, pins the
  original TLS hostname, and rejects redirects, compression, ambiguous headers, duplicate JSON,
  oversized bodies, and timeout detail leakage.
- Credential and backup imports are authenticated and bounded by request, archive, entry,
  expanded-byte, and count limits. ZIP content is processed in memory rather than extracted into
  the filesystem; unsafe names, encryption, and symbolic-link entries are rejected where relevant.
- Dynamic frontend values inspected in HTML-building paths are passed through text nodes,
  `escapeHtml`, or `escapeAttribute`; the Playground additionally has an executed inert-XSS test.
  The CSP forbids inline script and script attributes and denies framing.
- The tracked-secret scan found no private-key files or tracked `.env`. High-signal token and
  credential-URI matches were documentation placeholders only. `.dockerignore` excludes local
  environment, data, tests, logs, docs, and key material from the image context.
- `pip check` reported no incompatible installed packages. `pip-audit 2.10.1 --local` queried PyPI
  on 2026-09-11 and reported **no known vulnerabilities**.

## Accepted Bounded Residual Risks

- Unsafe cookie requests with an explicit cross-origin `Origin` or `Sec-Fetch-Site: cross-site`
  are rejected. A client supplying neither header is accepted for compatibility; SameSite=Lax is
  the remaining browser boundary. The independent review accepted this posture for the stated
  self-host target.
- The public inference API retains Gemini-compatible `?key=` authentication. Console examples use
  headers and dynamic responses are `no-store`, but an operator-controlled proxy or client can
  still record a URL credential. The installation guide now requires query-free access logging on
  `/v1beta/*`; removing this compatibility path is outside R1.
- OAuth flow state remains bounded process memory. Restarting during authorization requires the
  operator to start again; one worker and one replica are required by the supported R1 topology.
- The container entrypoint begins as root only to prepare the mounted data directories, then execs
  the application as UID 10001. The canonical Compose service uses a read-only root filesystem,
  no-new-privileges, bounded tmpfs/logging, and one durable data volume.
