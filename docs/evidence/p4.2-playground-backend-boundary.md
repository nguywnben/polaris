# P4.2 — Playground Backend Boundary

Date: 2026-09-10
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

Polaris now exposes `POST /api/playground/runs` as an authenticated, ephemeral control-plane
boundary around the same public inference handlers used by external clients. It supports OpenAI
Chat Completions, OpenAI Responses, Anthropic Messages, and Gemini generate/stream requests without
introducing a second routing, compression, guardrail, cache, provider, usage, or error pipeline.

The closed `playground-request.v1` wrapper owns the protocol, virtual or concrete model, stream
choice, and timeout. The nested `request` remains native to the selected protocol. It cannot
override the wrapper's model/stream controls or supply API keys, authorization, credential fields,
or transport headers.

## Production Bounds and Access

- Active operator permission (`credentials.operate`) or owner access is required; viewer access is
  denied by the central management-route manifest.
- The endpoint has a 1 MiB body ceiling enforced before JSON parsing for both fixed-length and
  chunked requests.
- A process-local limiter admits 20 runs per authenticated principal per 60 seconds and bounds
  tracked principals at 10,000. This matches the supported R1 single-worker topology.
- A request timeout defaults to 60 seconds and is constrained to 1–120 seconds. Timeout and client
  cancellation close the underlying public response iterator.
- No provider credential is accepted by or returned from the Playground contract.

## Response, Streaming, and Metadata Contract

Non-streaming responses retain the public handler's native body, status, and safe headers. A
base64url-encoded UTF-8 JSON document is added in `X-Omni-Playground-Metadata`. Streaming responses
relay native chunks unchanged and finish with an `omni.playground.metadata` SSE event. Disconnects
do not attempt to emit a final event.

The bounded `playground-metadata.v1` document contains request ID, protocol, requested model,
selected provider/model, status/outcome, duration, attempt/fallback counts, token/cost usage, quality
profile/revision, and the compression decision with before/after estimates. It contains no prompt,
output, client identity, provider credential, or raw upstream error.

Native request validation returns the selected public protocol's 400 envelope. Public handler
status and safe headers survive the boundary; translation failures become native 502 responses and
deadlines become native 504 responses. Outer wrapper validation remains the management API's 422
contract because a valid target protocol may not yet exist.

## Privacy and Operations

The boundary stores neither request nor response content and adds no schema, migration, dependency,
worker, or service. It binds the existing request-trace collector only for content-free route,
quality, usage, and status decisions. The existing exact-response cache still follows the saved AI
Quality policy; its balanced/default profile is off, while an operator who explicitly enables it
accepts the existing cache behavior for Playground calls because they use the real gateway path.

Each completed, timed-out, failed, rate-limited, or cancelled run produces one classified
`inference.execute` audit outcome and one structured completion log. Prometheus exports a
fixed-cardinality run counter and duration histogram labeled only by allowlisted protocol and
outcome. Operators can answer:

- Is a protocol failing or slowing down? Use `omni_playground_runs_total` and
  `omni_playground_run_duration_seconds`.
- Did one run time out, cancel, or fail? Correlate the structured completion log and audit event by
  request ID.
- Which route and quality policy affected an answer? Decode the response metadata header or inspect
  the final stream metadata event.

## Verification

- RED first: the focused suite initially failed because the Playground module and route did not
  exist; a later public-HTTP-error test exposed an incorrect generic 500 mapping before correction.
- Focused GREEN: **18 Playground tests** cover closed validation, nested credential rejection,
  authentication, operator/viewer authorization, fixed and parsed body bounds, per-principal rate
  limiting, all four protocol dispatches, native success/error behavior, timeout, streaming,
  cancellation, redaction, audit, and bounded metrics.
- Fixed task gate: lint and format for 438 files, compilation, the 193-core/13-experimental test
  partition, recursive JavaScript, strict YAML, six shell checks, whitespace, and **72 affected
  tests** passed. The first sandboxed attempt stopped at the known Windows Git Bash signal-pipe
  error 5; the identical approved outside-sandbox run passed.
- Restarted runtime: `/ready` returned 200 with storage, usage ledger, and coordination available.
  A new local-owner session then submitted an intentionally incomplete OpenAI Chat request through
  the deployed endpoint; it returned the native `invalid_request` 400 envelope plus request-ID and
  Playground metadata headers without contacting a provider.
- Product inventory and management authorization/audit coverage include the new route. The raw
  candidate compatibility check was also run: four of six tests passed, while two reported only the
  already-known `PUT /api/model-pools/omway` change caused by the unrelated unstaged request-schema
  edit in `backend/core/models.py`. P4.2 only adds a new endpoint and changes no frozen public
  contract.

The final review covered correctness, API compatibility, architecture, security/privacy,
performance, observability, test readiness, and maintainability. It corrected nested transport
credential acceptance, ensured cancellation cannot prevent upstream cleanup, and moved metrics out
of the panel module so the shared metrics layer does not depend on a route implementation. No
Critical or remaining Required findings were found.
