# P2.3 — Cross-Protocol Contract Corpus

Date: 2026-09-09
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

The five advertised inference families now have one versioned feature-disposition matrix and
shared request/response golden corpora. Tests cover text, data-URL images, system/developer
instructions, tool definitions and history, JSON-schema output, reasoning input/output, usage,
finish reasons, and native error envelopes for OpenAI Chat, OpenAI Responses, Anthropic Messages,
Gemini, and both Vertex aliases.

Public request models fail closed on unknown top-level and typed nested fields. Recognized but
untranslatable reasoning controls, content types, remote image references, and Anthropic redacted
thinking history are rejected with protocol-native HTTP 400 errors instead of being ignored.
Unknown upstream response parts produce protocol-native HTTP 502 errors.

## Correctness fixes

- OpenAI `developer` messages now retain system-instruction semantics.
- Responses `text.format` and Anthropic `output_config.format` now reach provider structured-output
  configuration.
- Official Anthropic thinking `signature` survives request and response translation.
- Responses output now contains a reasoning summary item when canonical output contains reasoning.
- Cached Gemini prompt tokens stay inside OpenAI prompt/input totals, as required by the Gemini
  usage definition. Reasoning is counted exactly once in generated output across Gemini, OpenAI,
  Responses, Anthropic, xAI, and Codex adapter boundaries.
- Length and safety finish reasons no longer claim a normally completed Responses/Anthropic result.

## Focused development evidence

The three TDD slices first exposed missing strict contract infrastructure, lost developer/system
instructions, missing Responses/Anthropic structured output, discarded signed thinking, incorrect
cached/reasoning usage, missing Responses reasoning output, and unsafe unknown response parts.
After correction, 103 directly affected tests passed across the corpus, protocol errors, Responses,
streaming-shape regression, model pool, request normalization, Anthropic, xAI, Codex, and OpenAI
provider modules.

## Task gate

The single fixed task gate passed backend/tool lint and formatting across 421 files, Python
compilation, the `core=179`/`experimental-ha=13` partition audit, recursive JavaScript syntax,
strict YAML, six deployment shell syntax checks, and whitespace checks. Git Bash initially stopped
inside the Windows sandbox with `Win32 error 5`; only the six shell checks were rerun outside the
sandbox and passed.

The focused gate ran 109 tests and exposed two compatibility failures: strict runtime Pydantic
models had changed 11 public OpenAPI hashes, while one pre-existing uncommitted virtual-model
validator changed one management hash. Runtime fail-closed validation was moved to schema-neutral
validators and hidden compatibility fields, restoring every frozen public hash without weakening
the runtime behavior or editing the immutable fixture. The unrelated virtual-model line was
temporarily removed only for the compatibility check and restored byte-for-byte afterward.

After that correction, all 103 affected protocol/provider tests and all five immutable
compatibility tests passed. Per the accepted cadence, authenticated deterministic end-to-end
browser/integration coverage for each public protocol runs once at the Phase 2 exit, not inside
P2.3.

## Post-implementation review

The final multi-axis review found no remaining critical or required finding. It did catch one
request/response boundary issue before closure: `reasoning_content` was rejected by the shared
message model, which also parses provider responses. The restriction now belongs to the Chat
Completions request model, so request history still fails closed while provider reasoning output
remains valid. The post-review focused slice passed 57 tests plus 32 parameterized subtests.

`backend/core/models.py` is now slightly above 1,000 lines, so extraction was assessed explicitly.
It remains below the project's 1,500-line hard limit, and the new validation stays beside the
protocol data models it governs. Splitting it during this correctness task would add indirection
without reducing runtime or ownership risk; no extraction was added to the fixed plan.

The final compatibility comparison reports no changed public inference operation. Its sole
remaining difference is the pre-existing, user-owned hardening of
`PUT /api/model-pools/polaris`, which was neither modified nor committed by P2.3.
