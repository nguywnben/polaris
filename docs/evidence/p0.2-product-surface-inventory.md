# P0.2 Evidence — Product Terminology and Navigation Inventory

## Result

P0.2 is complete. Polaris now has one checked product-surface inventory for the fixed
Production Self-Hosted R1 profile. Active pages, API operations, Settings controls, example
environment variables, advertised claims, documents, and locale ownership all have an explicit
support tier and owner journey.

## Delivered Inventory

The machine-readable contract is `docs/audits/product-surface-inventory.json` (schema version 1,
profile `self_hosted`). It records:

- 11 active page fragments and their 11 sidebar tabs;
- 134 active OpenAPI operations covered by 18 non-overlapping route groups;
- 24 Settings controls;
- 123 `.env.example` variables covered by 13 non-overlapping configuration groups;
- 16 advertised product claims;
- 7 active planning/product documents with checked relative links;
- English and Vietnamese as maintainer-curated Core locales, with the other 13 locales retained as
  community-maintained Compatibility surfaces.

The contract is intentionally an inventory, not the navigation redesign. Audit and request-trace
pages are marked for the already-planned P4.5 Activity merge, while optional Identity is marked for
conditional navigation in P3.1. No new phase, task, or denominator was created.

## Product-Copy Corrections

- Replaced the broad stable/enterprise framing with the approved production self-hosted boundary.
- Declared Docker Compose the canonical R1 production deployment path.
- Labeled PostgreSQL, OIDC team access, reverse-proxy operation, and external telemetry as Advanced.
- Labeled MongoDB and community locales as Compatibility.
- Labeled Redis coordination and Kubernetes/Helm assets as Experimental and removed suggestions
  that Redis enables production scaling or session acceleration.
- Replaced the console heading “Governance” with “Access & team” / “Truy cập và nhóm”.
- Removed historical Wave identifiers and enterprise terminology from `.env.example`.
- Applied the same boundary corrections to the curated Vietnamese README.

## Review

- Correctness: inventory coverage is derived from the actual fragments, sidebar markup, OpenAPI
  schema, Settings markup, and `.env.example` rather than hand-count assertions.
- Product clarity: active English and Vietnamese copy now matches the fixed R1 support boundary.
- Maintainability: future surface additions must be classified or the focused contract fails.
- Scope: no navigation restructuring or unfinished-HA isolation was pulled forward from P3.1/P0.3.
- Security and performance: static metadata and tests only; no secret values, external I/O, new
  endpoint, or production hot-path work.

Verdict: approved for the production self-hosted baseline.
