# P4.6 — Settings, Team Access, About, and Localization Evidence

Date: 2026-09-11

Plan: `PROD-SELFHOST-R1`

Result: **PASS — Phase 4 complete**

## Outcome

The remaining console surfaces now describe the actual self-hosted product boundary instead of
exposing implementation details without context. Settings is derived from the authoritative typed
schema, optional team login stays secondary when disabled, local-owner recovery remains explicit,
and About reports the running build and capability support tiers. English and Vietnamese are the
curated product languages; every compatibility locale retains a complete English fallback.

P4.6 also closed two Phase 4 integration defects found by the exit gate: the Settings response no
longer returns the reusable Code Assist client secret, and the pre-R1 virtual-key PATCH contract
again accepts clients that do not yet send an optimistic revision. The current console still sends
the revision, while the new rotate and revoke operations continue to require it.

## Implemented Surface

### Settings

- All **20** System Settings controls carry an explicit `data-config-key` matching the
  authoritative `CONFIGURATION_FIELDS` system surface exactly.
- Each control renders its Basic/Advanced/Experimental group, live/restart/read-only application
  mode, environment ownership, and configured-secret state from server metadata. Incomplete or
  invalid metadata fails closed instead of silently enabling an ambiguous form.
- Numeric zero is no longer replaced by a fallback value. Environment-owned fields are omitted
  from saves, and a blank client-secret field means “keep the configured value.”
- `GET /api/config/get` removes every reusable secret defined by the configuration schema plus the
  legacy password aliases. It returns only bounded `*_configured` booleans where needed.

### Optional Team Access

- The direct Team access page explains ready, disabled, invalid, and unavailable OIDC states.
- Disabled OIDC is presented as normal for single-user operation, while local-owner recovery and
  password readiness remain visible.
- Session invalidation is hidden unless OIDC is ready and the current principal has permission.
  The primary navigation continues to hide Team access when optional OIDC is not enabled.

### About and Operations

- About renders validated build version, revision, build date, and an explicit source of container,
  Git checkout, or development build.
- The authenticated capability registry is summarized as Core, Advanced, Compatibility, and
  Experimental, with active/available/disabled/blocked counts for each tier.
- Update/rollback and backup/restore guides stay visible regardless of whether a newer release is
  available. Remote runtime values are length/type bounded and rendered with `textContent` only.

### Localization and Access Compatibility

- The feature-owned catalog adds complete English and Vietnamese copy for schema state, support
  tiers, maintenance, build source, and optional-team recovery. All other supported locales receive
  the same complete English fallback.
- The JavaScript audit now recognizes valid dotted locale keys, eliminating a false positive
  without weakening literal detection.
- The Access quickstart again provides runnable cURL, Python SDK, and Node.js SDK examples for
  OpenAI, Anthropic, and Google GenAI. Every example uses `YOUR_POLARIS_VIRTUAL_KEY`; no console session
  or stored credential is interpolated.

## English/Vietnamese Semantic Review

The English copy consistently distinguishes application mode from support tier and says when a
restart is required. Vietnamese uses operator-facing terms (`Áp dụng ngay`, `Cần khởi động lại`,
`Do môi trường quản lý`, `Khôi phục bằng chủ sở hữu cục bộ`) rather than literal word-for-word
translations. “Team access” is described as optional login for a trusted group, not commercial
multi-tenancy. “Experimental” is explicitly outside the R1 production commitment in both languages.
