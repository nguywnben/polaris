# P3.1 — Navigation and Conditional Complexity

Date: 2026-09-10
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

The console now follows the fixed self-hosted information architecture: Overview, Providers,
Credentials, Models & Routing, AI Quality, Access, Activity, Settings, and an Advanced disclosure
containing conditional Team access and About. The former top-level Audit and Logs destinations no
longer compete with the daily workflow.

Activity is one page with accessible Request traces, Audit & security, and Runtime logs tabs. This
task consolidates ownership and navigation only; common cross-view filters, correlation pivots, and
export refinements remain bounded to P4.5. Existing `/audit` and `/logs` URLs still render Activity
and select their compatible view, while their frozen route-map entries remain unchanged.

Team access is fail-closed in navigation when OIDC state is disabled or unavailable. It appears
when enabled and remains reachable at `/identity` during direct configuration. Runtime-log controls
are collapsed as Advanced Settings; legacy Code Assist and hosted keep-alive controls are collapsed
and recorded as Compatibility settings. No experimental control enters the primary journey.

## Accessibility and responsive behavior

- A localized skip link targets the focusable main content region.
- User-initiated page changes move focus to the active page heading.
- Activity uses the ARIA tab pattern with roving `tabindex`, arrow keys, Home, and End.
- At mobile width, the closed sidebar is both `aria-hidden` and inert. Opening moves focus into the
  drawer; Escape closes it and restores the original trigger even after a resize-state sync.
- The Advanced navigation disclosure opens automatically for its active destination.

## Post-implementation review

The five-axis review covered correctness, readability, architecture, security, and performance. It
found and corrected:

1. compatibility URLs initially changed their frozen internal route-map values even though the
   pages still loaded; the old entries now remain stable and only the display layer maps them into
   Activity;
2. mobile resize synchronization could replace the original drawer focus-return target; the target
   is now captured only on the closed-to-open transition and has a regression test; and
3. repeated local restarts left four verified Polaris listeners sharing port 4283, producing
   nondeterministic old/new responses during smoke. Those exact processes were stopped before the
   clean single-runtime verification.

The change adds no dependency, frontend framework, database migration, background worker,
enterprise tenant construct, or experimental HA activation. Existing audit, trace, and log APIs,
redaction boundaries, pagination, retention, and authorization remain unchanged.
