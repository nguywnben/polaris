## Production Corrections Made from Evidence

The first fixed-profile execution established a failing baseline rather than causing the thresholds
to be relaxed. Focused diagnosis led to bounded production corrections:

- successful credential-use bookkeeping coalesces exact call increments instead of writing the
  same success state for every request;
- successful request trace/audit persistence begins after the response is delivered, while error
  and cancellation durability remains synchronous;
- SQLite Dashboard aggregation runs as bounded SQL rather than materializing and decoding the
  ledger in Python, and the usage ledger reuses one lifecycle-managed connection;
- Dashboard primary readiness no longer waits for its secondary detail table;
- the browser builds locale catalogs once rather than rebuilding six merged catalogs for each of
  664 translated elements, reducing the isolated translation pass from about 1,529 ms to 8.4 ms;
- the profile samples process memory outside the async load scheduler and settles the warm-up page
  before measuring reload, removing measurement-induced lag and cache races.

These changes preserve accounting, trace, cancellation, locale, and restart contracts. No load
level, timeout, threshold, replica, worker, database, provider, or soak duration was added or
relaxed.
