# P2.4 — Streaming, Cancellation, Timeout, and Retry Semantics

Date: 2026-09-09
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

All six public streaming surfaces now share a bounded, output-aware lifecycle. Disconnect and
cancellation propagate through nested adapters to provider iterators; HTTPX/wreq operations own a
read-inactivity timeout; retry is allowed only before model output; terminal events gate success;
and incomplete streams produce protocol-native failures.

The implementation adds no endpoint, dependency, configuration option, migration, or background
service. It reuses the current upstream timeout, retry settings, request trace, quota reservation,
credential lease, and protocol error shapes.

## Deterministic fault coverage

- Downstream send failure and explicit iterator cancellation close prefetched and nested sources.
- HTTPX line framing rejects an oversized line and preserves split CRLF frames.
- Primary routing suppresses retry after content, timeout, and a midstream error response; a
  heartbeat remains safe before retry; premature EOF cannot record success.
- Vertex enforces handshake/read timeouts, rejects an oversized JSON buffer, preserves a multibyte
  UTF-8 character split across transport chunks, and records success only after `finishReason`.
- OpenAI Chat, Responses, Anthropic, Gemini, Vertex OpenAI, and Vertex Gemini each have public
  adapter coverage for heartbeat framing and disconnect propagation.
- Anthropic retains a midstream failure as `event: error`; Responses emits `error` rather than
  `response.completed` when Chat lacks `[DONE]`.
- Cancelled streams release quota without fallback commit and persist one cancelled trace. An
  in-stream upstream failure overrides the outer HTTP 200 trace outcome.
- Responses, stream-to-non-stream, and anti-truncation aggregation paths enforce explicit caps;
  anti-truncation does not retry a read failure after output.

## Post-implementation review

The five-axis review covered correctness, security/privacy, performance/reliability,
maintainability, and test/operations readiness. It found and corrected four issues before closure:

1. a `Response` injected after output could still enter status-based retry handling;
2. Anthropic conversion could turn a midstream error into an empty successful stop;
3. Responses could claim completion without Chat `[DONE]`; and
4. Vertex replacement decoding could corrupt a UTF-8 character split between transport chunks.

Public error messages are bounded and generic. Traces keep only allowlisted status, provider,
model, retry, timing, and usage fields; prompt and generated content remain absent.
