# P2.6 — Compression and Quality-Policy Hardening

Date: 2026-09-10
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

Compression is now a bounded, explainable, provider-neutral decision. The estimator uses an
iterative one-million-node ceiling and tolerates deeply nested JSON without Python recursion
failure. Estimation errors, candidate-estimation errors, copy failures, and failed post-compression
invariants return the original request object with `estimation_failed` or `invariant_failed` rather
than interrupting inference.

Only a complete history prefix can be removed. System instructions, tools, tool configuration,
generation and safety settings, arbitrary structured top-level fields, recent complete turns,
tool-call/result pairs, and the current request remain unchanged. Semantic summarization, filler
removal, code thinning, and tool-output rewriting remain prohibited.

## Policy precedence and controls

The fixed R1 precedence is:

```text
deployment environment ceiling
  -> stored global policy
    -> virtual-key restriction
      -> per-request restriction
```

The two lower layers deliberately expose only `inherit` and `disabled`. A virtual key can be
restricted with revision checking through `PATCH /api/virtual-keys/{key_id}/quality-policy`; an
authenticated request can send `x-polaris-compression: off`. Neither can re-enable compression disabled
above it, change thresholds, or select a more aggressive mode. Invalid request overrides return
HTTP 400. Request-scoped values reset after every request.

The `quality`, `balanced`, and `capacity` presets retain bounded structural compression and
anti-truncation attempts of 5, 3, and 2 respectively. Preview and runtime both treat the configured
threshold as the inclusive no-compression boundary. Primary provider adapters resolve and apply one
compression decision before protocol conversion; Vertex streaming and non-streaming now use the same
policy and usage metadata.

## Post-implementation review

The five-axis review covered correctness, security/privacy, performance/reliability,
maintainability, and test/operations readiness. It found and corrected:

1. recursive estimation could fail on deeply nested or cyclic input;
2. estimator/copy failures interrupted inference instead of returning the original payload;
3. Preview and runtime disagreed at exact threshold equality;
4. global policy had no enforceable key/request restriction chain;
5. Primary repeated policy resolution inside provider branches;
6. Vertex bypassed compression policy and omitted compression usage metadata;
7. trace-reason and restriction normalization rules were duplicated; and
8. Phase-level localization had one uncatalogued password message.

No prompt, response, tool payload, API key, virtual-key secret, or raw estimator exception enters
telemetry. Public decision fields remain fixed-cardinality and estimates remain explicitly
non-authoritative.

## Scope and code balance
