# P1.6 — Supported Install Matrix

Date: 2026-09-09
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

Polaris now has one production installation path: the standalone, one-worker,
one-replica SQLite profile in `deploy/docker-compose.yml`. The linear guide runs from host checks
and an exact release checkout through a minimal `.env`, Compose validation, readiness, first-run
owner creation, authenticated Dashboard access, and persistence verification. README deployment
copy now points to that guide instead of presenting direct `docker run` as a competing production
workflow.

`deploy/install-support.json` is the checked support contract. Windows Docker Desktop/WSL2 and
Linux Docker Engine use the same Compose file. macOS Docker Desktop is the documented equivalent
with a bounded manual checklist. Native Python/Termux launchers, direct `docker run`, Render, and
Zeabur are compatibility paths; Helm remains experimental.

## Platform and architecture disposition

| Host | Status | Evidence boundary |
| --- | --- | --- |
| Windows + Docker Desktop + WSL2 | Core | Local clean setup, authenticated smoke, recreate persistence, and browser smoke |
| Linux + Docker Engine | Core | Required `ubuntu-latest` CI job builds and starts the canonical Compose profile, completes setup, recreates with durable state, and stops gracefully |
| macOS + Docker Desktop | Core equivalent | Documented manual check is required for the release because no macOS runner was available locally |

The publishing workflow contains exactly `platforms: linux/amd64`. `linux/amd64` is therefore the
only published production image platform. `linux/arm64` is explicitly `not-published`; the locked
provider dependency stack does not yet have equivalent ARM64 build and runtime evidence. Apple
Silicon amd64 emulation is compatibility-only and is not used to imply native ARM64 support.

## Contract and Phase 1 gate

The new install contract started with seven failing tests because the matrix, minimal Compose
environment template, guide, compatibility labels, and README routing did not exist. The final
focused install/Compose slice passed 13 tests.

The Phase 1 gate initially exposed two integration debts from earlier tasks: four P1.4 backup
operations lacked a product-inventory owner, and P1.3's use of `SecretStr` changed the protected
OpenAPI fingerprint for `POST /api/auth/setup`. The root fixes added the backup route group and
kept `SecretStr` redaction while projecting the original `r1-v1` string wire schema; the immutable
compatibility fixture was not overwritten.

Following the fixed cadence, already-passed work was not rerun indiscriminately:

- lint, format, compilation, suite partition (`core=177`, `experimental-ha=13`), JavaScript,
  strict YAML, shell syntax, and whitespace passed;
- the two failed inventory/compatibility modules passed all 14 tests after correction;
- all four translation commands exited successfully and 1,132 frontend keys remained complete;
- the remaining setup, backup, restore, update, and installation slice passed 61 tests; and
- the additional setup security/compatibility slice passed 27 tests, including secret-free errors
  and an explicit regression check that runtime representations cannot reveal setup secrets.

## Review

- Correctness: one version-pinned Compose guide reaches healthy authenticated operation and
  persists it across recreation.
- Security: no secret value is committed; setup secrets stay redacted in process; remote first-run
  setup still requires a strong operator token or preconfigured password; destructive volume
  removal is explicitly excluded from normal stop instructions.
- Compatibility: native installers and hosted descriptors remain available but no longer carry a
  production guarantee; the protected setup request schema remains stable.
- Maintainability: a small JSON contract and seven focused tests prevent documentation, script,
  architecture, and publishing claims from drifting independently.
- Scope: no new runtime service, dependency, database, platform abstraction, HA path, or release
  task was added.
