## Outcome

P5.6 closes the fixed 36-task production plan. Polaris 1.5.0 is prepared for production
self-hosting by one person or a trusted team on the supported single-worker, single-replica
standalone topology. The release does not claim enterprise service operation, production HA,
multi-replica coordination, or production Kubernetes support.

All 36 task IDs have one matching evidence record under `docs/evidence`. The maintained README,
configuration reference, architecture and identity documentation, installation, update, encrypted
backup/restore, troubleshooting, quality-gate and release-checklist guides were reconciled with the
same support boundary. The application version, pinned Compose image example, changelog entry, and
current Credential Pool screenshot now describe release 1.5.0.

## Operator Handoff

Use the maintained guides in this order:

1. [Installation](../installation.md) for the canonical pinned Compose deployment and first-run
   setup.
2. [Backup and restore](../backup-and-restore.md) to create and validate an encrypted recovery point.
3. [Updating](../updating.md) for immutable-image upgrade and the explicit rollback command.
4. [Troubleshooting](../troubleshooting.md) for health/readiness, request correlation, safe logs,
   recovery, and support-bundle data.
5. [Release checklist](../release-checklist.md) before tagging or publishing an image.

The rollback path is intentionally explicit: run `python tools/compose_update.py rollback` from the
repository root with the same environment and recovery bundle used by the update workflow. Do not
delete the named data volume to troubleshoot or roll back.

## Capability and Limitation Boundary

- **Core:** canonical Compose deployment, standalone runtime, one worker/replica, SQLite authority,
  public protocol compatibility, credential/provider/model workflows, AI Quality, Playground,
  virtual keys, Activity, backup/restore, update/rollback, and English/Vietnamese product copy.
- **Advanced:** opt-in PostgreSQL, OIDC Team access, external telemetry/export, proxy, guardrails,
  cache, and other controls documented in `deploy/compose.advanced.yml`.
- **Compatibility:** MongoDB and legacy/native/community deployment or locale surfaces retained for
  migration and existing users without the complete Core release evidence.
- **Experimental:** Redis coordination, multi-replica HA, Kubernetes/Helm, and their topology
  evidence. They cannot be used to infer a production support claim for 1.5.0.
- The published production image is qualified for `linux/amd64`; ARM64 qualification and editorial
  review of community locales remain post-R1 work.
- Real-provider account/quota checks are optional operator evidence. Deterministic provider and
  cross-protocol contracts are the release-blocking Core evidence.

## Release Actions and Working-Tree Boundary

No tag or push was performed by P5.6. Rebase, remote CI confirmation, annotated `v1.5.0` tagging,
image publication, digest verification, and announcement require an explicit operator release
decision and remain listed in the release checklist.

The pre-existing `backend/core/models.py` edit and two deleted historical W4.15 review reports are
user-owned changes. They were excluded from the detached candidate, release gates, and P5.6 commits.
