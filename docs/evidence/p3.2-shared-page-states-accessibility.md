# P3.2 — Shared Page States and Accessible Interaction

Date: 2026-09-10
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

The console now has one dependency-free page-state component for empty, error, stale, success, and
informational outcomes. Dashboard usage, provider credentials, routing models, AI Quality, virtual
API keys, and Settings use persistent error/remediation states instead of leaving first-load
failures blank. Refresh failures preserve previously loaded content and identify it as stale; retry
actions are bounded against repeated activation while the request is running.

Transient workflow feedback is exposed through atomic live regions. Errors use assertive alerts;
success, warning, and informational toasts use polite status semantics and remain visible for five
seconds. Existing destructive actions continue to use contextual confirmation dialogs rather than
browser-native `alert`, `confirm`, or `prompt` calls.

Shared modal mounting now traps Tab/Shift+Tab within the dialog, gives unfocused informational
dialogs a deterministic initial focus, removes its handler on close, and restores focus to the
connected opener. Reduced-motion preferences suppress nonessential transitions and animation.
Dashboard tables expose column-header scope, while all existing pagination regions have a named
navigation landmark and polite page-position status.

## Scope Boundary

This task standardizes shared interaction behavior only. It does not redesign Dashboard content,
provider onboarding, credential operations, or model routing; those remain P3.3–P3.6. Activity's
existing trace/audit/runtime loading and failure statuses remain owned by their specialized views.
No frontend framework, dependency, API endpoint, database schema, background worker, commercial
tenant concept, or experimental HA activation was added.

## Post-implementation Review

The five-axis review covered correctness, readability, architecture, security, and performance. It
found and corrected two required issues:

1. the prior max-mtime bundle version could remain unchanged when the asset manifest gained the
   new page-state module, allowing an immutable cached script to omit it. The version is now a
   stable digest of every asset path, modification time, and size; a regression contract proves a
   manifest change always changes the version; and
2. newly named pagination landmarks initially used fixed English `aria-label` text. They now use
   `aria-labelledby` references to the already localized section/page headings.

Untrusted API error text is rendered with `textContent`, not HTML. Page-state retries reuse the
existing authenticated loaders and add no independent data flow. No dead code or new dependency was
introduced. The three unrelated user-owned working-tree changes were not staged or modified.
