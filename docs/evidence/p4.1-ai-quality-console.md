# P4.1 — AI Quality Console Completion

Date: 2026-09-10
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

The AI Quality page now explains the effective request policy before an operator saves it. It
presents the existing `quality`, `balanced`, `capacity`, and validated `custom` profiles, states
that saved changes apply live without a gateway restart, and shows the fixed precedence chain:

```text
environment ceiling
  -> saved global policy
    -> virtual-key restriction
      -> request-header restriction
```

The page makes the compression-off contract explicit: no prompt context is pruned or rewritten and
threshold controls have no effect. When compression is enabled, it explains the inclusive threshold,
target, structural-only scope, protected structures, and fail-open unchanged-forwarding behavior.
Virtual keys and request headers are described accurately as restriction-only layers that can
inherit or disable compression but cannot re-enable it or change thresholds.

## Preview and risk communication

The authenticated, side-effect-free preview remains bounded to aggregate request metadata and does
not accept prompt content or call a provider. Its additive response now reports whether a transform
would occur, the complete-history-prefix scope, proportional estimated removed-message count, and
the unchanged-forwarding failure behavior. The console renders these alongside before/after/saved
token estimates and protected system/tool/recent-turn structures.

Stable warning codes identify configurations that need operator review:

- compatibility mode changing the system-instruction shape;
- fewer than three recent turns retained while compression is active;
- enabled guardrails with no active masking, injection, or keyword check;
- exact-response caching combined with returned reasoning content; and
- more than five truncation-recovery attempts.

Warnings are rendered with text nodes, not HTML. Numeric and collection limits remain enforced by
the existing Pydantic boundary and browser constraints. Optimistic revision conflicts continue to
return HTTP 409 and reload the latest policy rather than overwriting it.

## API compatibility

`GET` and `PUT /api/quality-policy` retain their request contracts and add response-only
`application` and `warnings` metadata. `POST /api/quality-policy/preview` retains its request
contract and adds `transformation` and `warnings` inside the preview result. No public inference
route, persisted schema version, dependency, worker, service, or migration changed.
