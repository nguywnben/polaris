# P2.5 — Routing, Fallback, Cooldown, and Health

Date: 2026-09-09
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

The standalone runtime now uses one canonical policy for eligibility, all five configured routing
strategies, model and credential fallback, bounded cooldown recovery, and route explanations.
Weighted routing accepts a seeded random source for reproducible fixtures; repeated failures grow
the delay to the configured cap instead of resetting after each expiry; success clears health.

No-route inference failures are truthful and actionable across missing, disabled, unsupported,
busy, oversized, and cooling credential pools. Authenticated operators can read a bounded,
secret-free recent snapshot at `GET /api/observability/routing`.

## Scenario matrix

The deterministic matrix verifies:

- `balanced` stable tie-breaking and rotation signals;
- `priority` preferred-provider selection plus healthy fallback;
- `weighted` exact seeded reproducibility and positive-weight behavior;
- `least_latency` measured latency buckets and an initial chance for unknown routes;
- `lowest_cost` local/subscription preference over metered provider variants;
- transient 429 fallback to a healthy credential and recovery at the bounded deadline;
- ordered virtual-model fallback after a credential-scoped 404; and
- actionable reasons for no credentials, all disabled, cooldown, unsupported model, capacity, and
  the 100-candidate ceiling.

## Post-implementation review

The five-axis review covered correctness, security/privacy, performance/reliability,
maintainability, and test/operations readiness. It found and corrected these issues:

1. weighted routing had no injectable random source, so a seeded fixture could not reproduce the
   decision;
2. cooldown expiry erased failure count, holding exponential recovery at its base delay;
3. public no-route errors misdiagnosed cooldown and capacity states as unsupported models;
4. raw routing decisions contained filenames and request IDs unsuitable for an operational API;
5. the new routing route and the earlier provider-capability route were absent from the fail-closed
   authorization manifest; and
6. an internal `limit=0` slice returned all recent decisions instead of none.

The public projection contains only normalized providers/models, stable vocabulary, aggregate
candidate counts, rounded retry delay, and an operator action. It excludes raw upstream errors,
credential filenames and payloads, request IDs, prompts, and responses.
