# P2.2 — Connection Tests and Actionable Provider Errors

Date: 2026-09-09
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

Credential model tests now return one versioned, provider-independent diagnostic contract. It
classifies credential, permission, quota, rate-limit, network, proxy, TLS, upstream, invalid-model,
unsupported-operation, timeout, cancellation, and internal outcomes. Each result contains a safe
summary, fixed remediation, retry guidance, and—when available—a bounded HTTP provider status and
an allowlisted provider error code.

The existing response remains backward compatible: `error` and `detail` are retained as strings,
but they now contain the normalized safe summary. The additive `diagnostic` object is the stable
machine-readable contract. HTTP 429 still proves provider connectivity and therefore remains a
successful connection check with a quota or rate-limit warning rather than a healthy-capacity
claim.

The console prioritizes the safe diagnostic, distinguishes limited outcomes from hard failures,
and presents remediation, provider status, provider code, and retryability without inserting raw
provider content into the DOM. Five supporting labels are complete across all 15 locale catalogs.

## Safety and cancellation

- Raw upstream response bodies and exception messages are no longer returned or persisted by the
  connection-test route. Unknown provider error codes are discarded.
- One 30-second deadline covers refresh, request preparation, provider I/O, and any Code Assist
  preview probe; nested adapter timeouts cannot extend the complete operation.
- Closing the test dialog or pressing Escape aborts the browser request. ASGI disconnect detection
  cancels the same provider coroutine, while caller cancellation remains cancellation rather than
  being converted to a generic failure.
- An unsupported provider operation now returns both the existing typed 422 envelope and the
  additive safe diagnostic before provider I/O or mutation.

The public contract and maintainer guidance are in `docs/provider-connection-diagnostics.md`; the
boundary decision is recorded in `docs/decisions/010-safe-provider-connection-diagnostics.md`.

## Deterministic coverage

`backend/tests/fixtures/provider-connection-errors-v1.json` defines stable provider responses for
every advertised provider/authentication variant: Google Antigravity, Google AI Studio, xAI
Console, Grok Build, Codex, OpenAI Platform, Claude Code, Claude Platform, and Ollama. The fixture
covers status-, provider-code-, and message-based classification without external credentials or
network access. A route-level disconnect test proves both the HTTP 499 cancellation result and
cancellation of provider/storage work.
