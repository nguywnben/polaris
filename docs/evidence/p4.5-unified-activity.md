# P4.5 — Unified Activity

Date: 2026-09-10
Plan: `PROD-SELFHOST-R1`
Status: complete

## Result

Activity now provides one investigation workflow for request traces, audit/security events, and
runtime logs. A single shared form owns the time range, canonical outcome, provider, actor type, and
public request ID. The client translates canonical outcomes to each existing bounded API contract,
keeps the values in memory only, resets cursors when they change, and applies them when operators
move between tabs.

Trace and audit detail dialogs can pivot to the related view with the same request ID. Dashboard
recent activity can open the correlated trace directly. The compatibility routes remain stable:
`/activity` opens request traces, `/audit` opens audit/security, and `/logs` now correctly opens
runtime logs.

## Safety and Bounds

- No prompt, response body, provider secret, credential filename, arbitrary metadata, or raw
  exception was added to an Activity contract.
- Shared provider, actor, and request identifiers are length- and character-bounded. Invalid time
  ranges fail before an API request, and correlation filters are never written to browser storage.
- Runtime matching examines at most 8,192 characters per already bounded WebSocket line. Existing
  WebSocket authentication, same-origin checks, server redaction, and line-count bounds remain.
- Trace export remains fail-closed above 10,000 records or 16 MiB. Audit export remains fail-closed
  above 10,000 events or 8 MiB.
- Raw-log download now reads only the newest complete lines within 16 MiB, redacts before release,
  and returns explicit byte-count, byte-limit, and truncation headers. It no longer streams the
  complete active log, whose configured rotation ceiling can be much larger.
- Trace, audit, and raw-log retention remain separate and keep their existing explicit controls.
