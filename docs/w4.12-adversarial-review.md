# W4.12 Adversarial Review Record

This record captures the fresh-context review cycles used to close the W4.12 Identity console.
The review contract was the locked W4.11 API plus the acceptance criteria in `tasks/plan.md`.

## Cycle 1

Findings and reconciliations:

- Identity CAS conflicts reused shared draft state and did not always refetch the conflicted
  resource. Create and per-identity role drafts are now independent; HTTP 409 refetches the
  resource, reapplies only the matching role draft, and returns focus to the refreshed control.
- Advancing the OIDC authorization epoch left the current OIDC console visually authenticated.
  Successful epoch advancement now clears the Identity state and signs out an OIDC principal.
- Permissions, page records, and sessions were trusted as unbounded collections. The client now
  rejects more than 64 permissions and more than 25 records per page before rendering.
- List replacement lost keyboard focus. Successful refreshes now return focus to the matching
  refreshed control or a stable status boundary.
- Initial tests asserted source strings without executing client behavior. The Identity contract
  suite now evaluates the client contract in Node and exercises permission and mutation paths.

## Cycle 2

Findings and reconciliations:

- Self enablement or role changes revoke an OIDC principal's sessions server-side, but the client
  did not sign out. Both workflows now sign out before any refetch when the target is the current
  OIDC identity.
- Principal, permission, draft, cursor, dialog, and tab-cache state could cross an authentication
  boundary. Login, setup, logout, failed setup-status authentication, and Identity-triggered
  sign-out now share one complete reset path.
- A previously rendered OIDC epoch control could remain visible after permission or policy loss.
  Every OIDC render now derives its visibility from the current validated policy and permission.
- OIDC scopes were filtered before collection size was bounded. Oversized scope collections are
  now rejected before mapping or rendering.
- Workflow coverage did not prove conflict refetch, draft preservation, focus restoration, or
  sign-out cleanup. Executable regression cases now cover each outcome.

## Cycle 3

Finding and reconciliation:

- Four secondary resource requests could complete after logout and repopulate the next principal's
  browser state because only the current-session request was abortable. One controller and one
  generation token now guard the principal, identity, session, OIDC, and recovery loads. Reset
  aborts the controller and advances the generation. A regression test proves a stale response is
  ignored even when the mocked transport does not honor abort.

## Final primary-agent review

A final fail-safe review found that an HTTP 401 from an Identity resource left the surrounding
console looking authenticated. The Identity transport now performs the same complete reset and
navigates to login before rejecting the request. The behavioral contract verifies that principal
state, drafts, permissions, cursors, dialogs, and the Identity tab cache cannot survive that path.

The same-model adversarial loop stopped after three cycles as required. Cross-model review is kept
as a separate W4.12 release gate and its result must be reconciled before the slice is committed.
The first authorized external attempt and its authentication blocker are recorded in
[W4.12 Cross-Model Review Record](w4.12-cross-model-review.md).

## Authenticated browser closure

The final real-browser pass found three release-blocking integration defects that static and
mocked contracts had not exposed:

- The verified panel token is a string-compatible security wrapper, while the session store
  intentionally accepts only an exact built-in string. Passing the wrapper through the Identity
  context made a valid opaque session fail `GET /api/identity/session` with `SessionNotFound` and
  HTTP 503. The authenticated boundary now converts the already-verified value to an exact string
  before session lookup; a regression test reproduces the wrapper/store boundary.
- Identity dialog aliases looked only in the keyed message catalogs even though `btn_cancel` and
  `btn_close` remain in the legacy catalog. Every supported locale therefore rendered those raw
  keys. Alias resolution now uses each locale's existing legacy translation before fallback, and
  an executable 15-locale test rejects raw alias keys.
- Chromium did not close the native create dialog through the existing `cancel` listener during
  keyboard testing. Create and confirmation dialogs now also handle Escape at the focused dialog
  boundary, prevent the native default, close through the shared cleanup path, and restore focus.

After reconciliation, the authenticated console returned HTTP 200 for current session,
identities, sessions, OIDC policy, and recovery. Widths 360/768/1024/1440 had no horizontal
overflow; system/light/dark themes and Vietnamese/English/Simplified Chinese passed; create-dialog
focus, localized accessible names, and Escape behavior passed; and browser warning/error logs were
empty. No identity, session, or policy mutation was submitted during verification.
