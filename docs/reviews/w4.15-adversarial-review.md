# W4.15 adversarial review reconciliation

## Review boundary

This review covers the versioned coordination-store contract, the in-process reference store, the
Redis transport and Lua scripts, quota reserve/commit/release semantics, fencing epochs,
invalidation, replay/expiry indexes, cancellation behavior, metrics, and opt-in live Redis parity
evidence. It covers the complete W4.15 range from the W4.14 checkpoint through the Task 6 closure
fix wave.

A fresh-context internal review found 12 issues. At the human's request, an independent Gemini
3.7 Flash/Antigravity review was also performed and saved outside the repository as
`C:\Users\nben6\Downloads\w4.15-cross-model-review.md`. That report returned no findings. Its
verdict is rejected as a false negative because it says token arithmetic is string-based when the
reviewed Lua used `tonumber`, and says the test fake matched production ordering when the fake
pruned before replay while Lua evaluated replay first. The external report supplied no additional
finding.

## Findings and disposition

| Severity | Finding | Disposition |
| --- | --- | --- |
| Critical | A missing epoch could silently bootstrap epoch 1 during normal mutation, allowing partial Redis loss to reset fencing authority. | Fixed. A persistent initialization marker and epoch record are provisioned atomically only by `read_epoch()`. Normal epoch, CAS, invalidation, and quota mutations fail closed if the pair is absent, partial, malformed, or expiring. |
| Critical | Lua aggregated signed-63-bit token values with binary64 arithmetic and lost precision above 2^53. | Fixed. Token aggregation uses exact decimal-string addition and comparison with fail-closed saturation above the signed-63 domain. Boundary coverage includes 2^53 - 1, 2^53, 2^53 + 1, and signed-63 maximum. |
| Critical | Quota scripts could replay an already-expired operation before atomically pruning it. | Fixed. Due replay evidence is excluded before replay/conflict decisions, then pruned in the same mutation. Identical and changed operations are re-evaluated after retention. |
| Important | The in-process quota store trusted caller `request.now` for coordination expiry and rate windows while Redis used server time. | Fixed. Each mutation captures the store clock once; caller time remains validated business evidence only. Forward- and backdated parity cases are covered. |
| Important | In-process cleanup could partially mutate before reporting excess backlog, stale heap nodes consumed work, reads pruned state, and unrelated categories shared a cleanup budget. | Fixed. Cleanup now preflights transactionally, ignores replaced heap nodes, keeps reads side-effect free, and uses operation/category-local budgets. |
| Important | Stored quota decimals allowed non-finite/oversized values and committed records allowed impossible chronology. | Fixed. Numeric fields are parsed once into bounded finite values; exact-safe timestamps and `accepted_at <= committed_at <= active_until` are enforced before mutation. |
| Important | The quota release decoder accepted the impossible `(released=1, idempotent=1)` reply. | Fixed. Only `(0,0)`, `(1,0)`, and `(0,1)` are accepted. |
| Important | `RedisStateStore.close()` could become permanently closed or lose the client after cancellation/failure. | Fixed. Concurrent callers share one shielded close task, new work is rejected while closing, successful cleanup alone marks the store closed, and a failed close can retry the same client. |
| Important | The stateful Redis test driver modeled intended quota order rather than Lua execution order. | Fixed. Shared quota lifecycle, replay, expiry, capacity, time-source, and large-integer cases run through the stateful registered-script driver; opt-in live tests cover the same risks when a Redis URI is supplied. |
| Important | A 100,000-record per-key quota mutation can execute an O(n) `HGETALL`/`ZSCORE` scan on the Redis thread. | Accepted pre-activation boundary. W4.19 must establish a measured supported cap/topology or redesign before activation. Deterministic W4.15 tests are not scalability evidence. |
| Minor | Negative zero serialized differently across backends. | Fixed. Signed float zeros canonicalize to ASCII `0`. |
| Important contract ambiguity | The contract did not explain how a genuinely new namespace differs from a lost epoch. | Fixed in the maintained specification. The durable marker distinguishes partial loss; complete namespace deletion remains an unsupported operational loss that W4.18 must protect and reconcile before activation. |

## Five-axis review verdict

- Correctness: approved. Fencing, replay, cleanup, quota lifecycle, exact token arithmetic,
  chronology, and cancellation have regression coverage and the full backend suite passes.
- Readability: approved. Coordination policy remains at the typed store boundary; Lua validation,
  planning, and mutation phases are explicit despite the unavoidable script size.
- Architecture: approved for pre-activation semantic parity. No caller, runtime authority,
  readiness, worker, replica, or deployment selection moved to Redis.
- Security: approved. Corrupt/partial state fails closed, scripts use application-owned fixed Lua
  with explicit `KEYS`/`ARGV`, and no identifier, credential, URI, exception detail, or secret was
  added to metrics or review evidence.
- Performance: conditionally approved for inactive primitives only. The bounded O(n) quota scan is
  a recorded activation blocker owned by W4.19.

## Accepted boundaries and follow-up

- `POLARIS_TEST_REDIS_URI` is not configured. Live Redis tests skip explicitly; stateful driver tests
  execute registered script behavior, but neither they nor static Lua assertions are live-service
  evidence.
- Whole-namespace Redis loss cannot be distinguished from a first-use namespace. W4.18 must add
  backup/restore, reconciliation, and deletion protection before coordinated activation.
- W4.15 does not select Redis at runtime, change `/ready`, migrate callers, or enable multiple
  workers/replicas. Standalone in-process authority remains unchanged.
- W4.16 is the next slice and may coordinate identity/session/security state only through the
  reviewed W4.15 boundary. Routing, quota/cache caller migration and scale activation remain gated
  by W4.17-W4.19.

## 2026-09-05 Quota State v2 follow-up

The O(n) item above is retained as historical W4.15 context and is now resolved at the algorithmic
boundary by the approved Quota State v2 design and implementation. Reserve, commit, and release no
longer enumerate retained lifecycle records: each transition reads one directly addressed record,
exactly 61 fixed second buckets, and at most 256 due lifecycle/replay entries after a 257-item
preflight. The old quota v1 Lua bodies were removed so there is no dormant full-scan path in the
runtime module.

A 100,000-retained-record synthetic fixture observes the same `(1 record, 61 buckets)` work as a
small fixture. Bounded dry-run/apply reconciliation prevents v1, active, corrupt, expiring-marker,
or incompletely scanned state from becoming ready; `mark-ready` independently confirms completion.
The follow-up review also corrected valid v1 committed chronology, schema-marker validation order,
non-canonical cursors, invalid identifiers/counts, duplicate scan candidates, and forged drain
completion evidence.

This closes the former performance-design finding, not the separate activation gate. No live Redis
URI or working container daemon was available, so live latency, failure, and two-replica topology
evidence remain unclaimed.
