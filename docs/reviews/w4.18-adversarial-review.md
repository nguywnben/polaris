# W4.18 adversarial review — HA runtime lifecycle

## Scope and disposition

Reviewed the complete uncommitted W4.18 runtime policy, persistent binding, lifecycle injection,
readiness/metrics, operator commands, deployment assets, alerts, runbook, and affected tests against
the accepted HA lifecycle contract. The implementation remains one-replica and fail-closed; the
W4.19 activation allowlist is intentionally empty.

## Findings reconciled

| Severity | Finding | Resolution |
| --- | --- | --- |
| Critical | The primary provider API owned a second direct Redis client and silently fell back to process memory. That permitted divergent conversation steps after dependency loss and exposed raw session identifiers in Redis keys. | Replaced it with lifecycle-injected, epoch-fenced CAS state. Keys are HMAC-derived, payloads use a closed schema, concurrent increments are atomic, and dependency/corruption errors fail closed. |
| Critical | MongoDB's legacy Redis acceleration reused `REDIS_URL`, so coordinated deployments could mix unnamespaced credential/config cache data with the coordination namespace. | Coordinated mode now disables the legacy MongoDB Redis cache. MongoDB remains durable authority; coordination uses only the namespaced fenced adapter. |
| Important | HA `status` read the epoch before proving the shared binding existed, which could hide namespace loss or initialize transport state before diagnosis. | Status now reads durable and shared bindings first, accepts only the exact current/one-prior transition set, and then reads epoch/drain state. Namespace loss fails closed. |
| Important | The runtime's default activation verifier was an unconditional denial rather than the compiled exact-record verifier, making a future evidence record unreachable. | Bound the default to `verify_ha_activation_record`; the current allowlist remains empty, so W4.18 behavior is still closed. |
| Important | Deployment examples omitted lifecycle identity, secret references, hard replica validation, and drain time. | Added standalone defaults, coordination secret references, a Helm one-replica render failure, 45-second termination grace, readiness alerts, and linked runbook guidance. |

## Evidence

- Focused HA, security, routing, cache, quota, identity, readiness, deployment, and lifecycle matrix:
  184 tests passed.
- Primary session concurrency: 12 simultaneous updates produced exactly steps 1 through 12; forced
  dependency loss and corrupt payloads failed closed.
- Compose configuration rendered successfully with standalone defaults.
- Ruff passed for every affected Python file; `git diff --check` passed.
- Helm CLI was not installed on the verification host. Static chart contracts passed, but Helm
  rendering is recorded as unavailable—not a pass.
- No `POLARIS_TEST_REDIS_URI` was supplied and Docker Desktop was not running. Live Redis evidence is
  unavailable and must not produce an activation record.

## Retained gates

- `SUPPORTED_HA_ACTIVATION_RECORDS` is empty.
- `WORKERS=1`, `POLARIS_REPLICA_COUNT=1`, and Helm `replicaCount: 1` remain enforced.
- Provider OAuth/device-flow state and W4.15's worst-case quota mutation cost must be included in
  W4.19 failure/load disposition before any multi-replica claim.
- Production activation, durable-authority mutation, live credentials, and source export remain
  outside this checkpoint.
