# W4.17 adversarial review reconciliation

## Review boundary

This fresh-context internal review covers W4.17 from `558baf5` through `2b3495c`: readable fenced
records, the routing/cache semantic adapter, credential admission, quota fencing, exact-cache
metadata, governance invalidation, metrics, Redis parity, and operator evidence. It evaluates the
inactive coordination path against ADR-006, ADR-008, and the accepted W4.17 specification.

No W4.17 source was transferred to an external model or review service. Redis live execution was
not available because `POLARIS_TEST_REDIS_URI` was absent; the live suite reports this as an explicit
skip rather than a pass.

## Threat-axis verdict

- Admission and fencing: approved for inactive use. Credential and quota admission carry the exact
  injected epoch; stale, reconciling, corrupt, unavailable, capacity, and retry-exhausted states do
  not fall back to process-local authority.
- Unknown outcomes and cancellation: approved. Transport uncertainty retries the same replay ID.
  Task cancellation after a committed acquire may retain one bounded lease and cannot authorize an
  extra exclusive admission before server-time expiry.
- Cache freshness: approved. Response bytes remain local. A hit requires current generation,
  matching HMAC-addressed metadata, content digest, media category, and a second generation read.
  Missing, corrupt, stale, mismatched, or unavailable evidence evicts and returns a cache miss.
- Governance freshness: approved for the durable-source model. Each cache owner has an independent
  generation cursor and rebinding revision. Successful config/credential mutations publish only
  fixed scopes; failures are surfaced instead of silently retaining a coordinated stale view.
- Bounds and performance: approved for the reference path. Candidate count is 100, leases 128,
  latency samples 10, CAS payload 16 KiB, and semantic CAS conflicts eight attempts. The 128-lease
  reference test completed in 78 ms on the development host. This is not Redis or HA load evidence.
- Secrecy and observability: approved. Domain-separated HMAC identifiers cross the store boundary;
  prompt, response, embedding, raw credential/model/cache/key identifiers, operation IDs, URIs, and
  exception details do not enter metric labels or operator evidence.
- Activation leakage: approved. Runtime selection remains in-memory, `WORKERS=1` and one replica
  remain the only supported topology, semantic cache remains inactive, and no deployment/readiness
  policy was changed. W4.18-W4.19 still own lifecycle and activation.
