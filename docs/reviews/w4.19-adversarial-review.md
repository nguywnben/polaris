# W4.19 adversarial review — HA evidence and Wave 4 closure

## Scope and disposition

Reviewed the complete W4.18 lifecycle and W4.19 evidence path as an activation adversary: assume
unit parity is insufficient, dependency loss happens between operations, callbacks reach another
replica, local locks do not coordinate processes, and skipped infrastructure can never count as a
pass. The resulting disposition is implementation-complete but activation-denied.

## Findings reconciled

| Severity | Finding | Resolution |
| --- | --- | --- |
| Critical | Synthetic in-process timing could be mistaken for the ADR-008 load gate. | The executable harness now labels itself non-activation evidence, emits `activation_eligible=false`, enumerates blockers, and the evidence report separates semantic proof from production capacity. |
| Critical | Provider OAuth/device-flow maps, batch idempotency reservations, and pool mutation locks remain process-local. A second replica could miss or duplicate state. | Retained as explicit activation blockers. The allowlist stays empty and every deployment surface remains one replica. |
| Important | The Redis quota mutation still scans a bounded but potentially large record set; no live worst-case result supports the latency target. | Recorded the exact 100,000-record ceiling and rejected activation instead of extrapolating from the in-memory harness. |
| Important | Running the evidence tool as `python -m backend.ha_evidence` failed under the repository's import layout. | Added a stable repository-root module entrypoint and a subprocess regression test. |
| Important | Frontend/backend localization audit tools missed supplemental locale catalogs, HTML void-element semantics, technical protocol values, and several management error classes. | Corrected the auditors, linked the remaining backend literals to a 15-locale security catalog or semantic mapping, and re-ran all audits successfully. |
| Important | A runtime lifecycle test left the singleton credential router bound to a closed coordination service, causing a later unrelated routing test to fail. | Lifecycle teardown now releases the owned router binding. The reproducing sequence and the full 1,254-test suite pass. |
| Important | A coordination outage made `/ready` label healthy storage and usage dependencies unavailable, obscuring root-cause diagnosis. | Readiness still fails closed with HTTP 503, but now probes and reports initialized durable dependencies independently. The full 1,254-test suite passes. |
| Minor | Three synchronous test helpers used a Python 3.16-deprecated loop policy API and leaked their event loops. | Switched to explicit `asyncio.new_event_loop()` ownership with async-generator shutdown and deterministic close; the affected 50-test matrix passes without those warnings. |

## Independent constraints retained

- No exact Redis/database/two-replica topology was available.
- Container and Helm execution were unavailable and are not reported as successful.
- No source was sent to an external reviewer for W4.18-W4.19.
- No production setting, durable record, provider credential, or remote service was mutated.
- W4-C human acceptance and any later HA activation remain separate gates.
