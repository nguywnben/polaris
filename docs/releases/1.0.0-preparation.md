## Product and compatibility boundary

Standalone, one worker, one replica, canonical Compose, SQLite Core; PostgreSQL and
OIDC are optional Advanced integrations, MongoDB is Compatibility. Redis, HA,
Kubernetes and distributed execution remain retired. Existing public SDK paths,
credential-scoped eligibility, fail-closed protocol semantics and permission checks
remain authoritative. No database migration or operator-data reset is part of this
version preparation. See [compatibility](../compatibility.md) and
[provider capabilities](../provider-capabilities.md).

## Upgrade and rollback

Back up the running deployment before upgrading. Follow the
[health-checked update and rollback procedure](../updating.md) with the verified new
digest, keeping the previous image digest and encrypted backup together. Keep the
same storage and namespace; do not delete volumes, reset databases or reimport real
credentials to change the product version. See [recovery](../backup-and-restore.md)
and [troubleshooting](../troubleshooting.md). A source-only rollback of this audit
does not require a data migration.
